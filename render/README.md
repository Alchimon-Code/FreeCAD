# Видовой экран PlaneDraft: от документа до пикселя

Для проверки на Windows запустите `build\windows-msvc\bin\PlaneDraft.exe --viewport-demo`. Это чертёж около `(10 000 000, −10 000 000)` с отрезками, окружностью, дугой, замкнутой bulge-полилинией и текстом. Пример добавляется **одной транзакцией**; обычный запуск открывает пустой документ. Приблизьте стык колёсиком, введите `_LINE` и укажите две точки по зелёным маркерам. `_UNDO` отменит только новый отрезок. `Ctrl+Shift+E` снова покажет чертёж целиком.

## Кто чем владеет

| Компонент | Ответственность |
|---|---|
| [`Camera2D`](camera2d.hpp) | Центр, логический размер, масштаб, преобразования, панорама, зум с якорем и вписывание AABB. |
| [`Viewport`](viewport.cpp) | `QOpenGLWidget` в главном окне; мышь, анимация, локальный выбор, поиск ручки и OSNAP. Передаёт мировую точку и ID в общий `EditController`, не пишет в `Document`. |
| [`SceneRenderer`](scene_renderer.cpp) | Один экземпляр на GL-контекст. Программы GLSL 450, VAO/VBO, порядок проходов. Создание, загрузка и удаление только при текущем контексте; при его пересоздании кэш строится заново. |
| [`SceneCache`](scene_cache.cpp) | Состав видимых пакетов, CPU-тесселяция, относительные вершины и причины перезагрузки. Для теста вместо GPU принимает обработчики `upload`/`evict`. |
| [`SnapEngine`](snap_engine.cpp), [`SelectionManager`](selection_manager.cpp) | Пространственный запрос → уточнение по геометрии. Не используют пиксели из FBO, сетку отображения или ID-буфер. |

`pd_render` зависит от Qt OpenGLWidgets/OpenGL и двух библиотек: [редактор](../editor/README.md) (`Qt Core`) и `pd_view_math`. Последняя включает камеру, выбор и подготовку геометрии и зависит только от `pd_core`. Обратной зависимости от Qt, шрифтов или OpenGL в ядре нет. Внешний C ABI v1 не изменился.

### Камера и точность

`z` — логические пиксели на единицу модели; Y модели направлен вверх. Для точки `P`, глаза `C` и размера `w × h`:

```text
screen(P) = (w/2, h/2) + (P.x − C.x, C.y − P.y) · z
world(s)  = C + (s.x − w/2, h/2 − s.y) / z
```

При увеличении от `z` до `z′` центр смещается на `(s.x−w/2, h/2−s.y) · (1/z−1/z′)`. Поэтому `world(s)` остаётся прежней с точностью `double`, в том числе при ограничении масштаба. Дробные дельты колеса/тачпада поддерживаются; 110-мс анимация вычисляет каждый кадр из начальной камеры, а не накапливает округления. Средняя кнопка смещает центр на `(-dx, dy)/z`. Zoom Extents берёт `Document::extents()` за O(1) у корня геометрического R-tree (включая скрытые объекты); оставляет поля, учитывает плоские границы, пустой документ не меняет камеру.

**Relative-to-eye (RTE).** При сборке пакета запоминается глаз `O = C`; CPU обрезает длинные сегменты по области с запасом и записывает `float(P − O)`, а не `float(P) − float(O)`. На кадр передаётся column-major `mat3` из `float`: масштаб `(2z/w, 2z/h)` и сдвиг `(O − C) · масштаб`, также рассчитанный в `double` до приведения. При небольшом pan меняется матрица, не вершины. Ограничение диапазона относительных координат (около 65 536 физических пикселей) вызывает пересборку даже прямолинейного пакета при глубоком приближении. Это не восстановит точность, уже потерянную самой моделью за пределами разрешения binary64.

### Какие данные пересылаются в GPU

1. При смене вида `doc.query(viewBounds)` возвращает видимые AABB-кандидаты. Ключ пакета — `EntityId / 256`, но геометрию загружают **только для ID из текущей выдачи**, а не для всех соседних ID. Для выделенных объектов учитываются и попавшие в вид внешние ручки. Опустевшие пакеты освобождаются.
2. Один пакет `Added/Modified/Removed` от сессии обновляет состав и dirty-флаги на CPU. Удаление обрабатывается по ID без висячего указателя. Для изменения слоя повторяется запрос видимости; стиль обновляется у пакетов с этим слоем. Выбор инвалидирует пакеты изменивших состояние ID. Сам вызов наблюдателя не делает GL-вызовов.
3. На `paintGL` перезагружается пакет, если изменились данные/состав, диапазон LOD кривых, вид вышел из области обрезки с запасом или нужна новая точка RTE. В остальном переиспользуются VAO/VBO. Смена только положения курсора не запрашивает заново весь вид и не отправляет вершины сцены.
4. На вершину — 12 байт: два `float` и нормализованный RGBA8. Цвет берётся через `Document::resolveStyle` (включая ByLayer); выделенный штрих — янтарный. Для `Text` Qt строит контуры системного шрифта из UTF-8, вписывает их в `localInk` с учётом `placement`. Отверстия глифов не соединяются фиктивными рёбрами. Модельное поле тёмное при обеих темах интерфейса, чтобы белый цвет слоя оставался различим.

**Допуск кривых.** [`tessellation.cpp`](tessellation.cpp) работает с окружностью, направленной дугой и каждой дугой из bulge, включая замыкающее ребро. Масштаб `s = z · devicePixelRatio`; верхняя граница интервала LOD `L = 2^ceil(log2(s))`. Для участка угла `Δ` стрела хорды `h = 2R·sin²(Δ/4)`. Начинаем с участков не больше четверти оборота; делим пополам, пока `h·L > 0,35`. Тем самым `h·s ≤ 0,35 < 0,5` **физического** пикселя до округления вершин. Малая окружность вдали обходится четырьмя рёбрами. Для огромной окружности вблизи до деления проверяется AABB хорды, расширенный на `h`: ветви вне области вида с запасом не разворачиваются. Привязки не зависят от LOD.

### Проходы OpenGL

* **Сетка:** [вершинный](shaders/grid.vert) и [фрагментный](shaders/grid.frag) шейдеры. Один полноэкранный треугольник. `glViewport` задаётся по округлённому физическому размеру FBO; при 150% и нечётной логической ширине или высоте не остаётся полосы от предыдущего кадра. Фаза крупных линий — остаток от деления координаты глаза на крупный шаг, рассчитанный CPU в `double`. По `gl_FragCoord` строятся сглаженные линии шагов 1/2/5 по декадам, каждая пятая линия усилена, оси выделены. Буфера линий сетки нет.
* **Сцена:** [stroke.vert](shaders/stroke.vert) / [stroke.frag](shaders/stroke.frag), `GL_LINES` на пакет. Никаких абсолютных мировых `float` и никаких `dvec2` в GLSL.
* **Оверлей без depth test:** в конце того же VBO хранятся синие ручки (`GL_POINTS`, размер в пикселях). Поверх них — [короткий экранный буфер](overlay.cpp): полупрозрачная рамка, штриховая направляющая, полупрозрачная геометрия `edit::Plan`, красная горячая ручка, перекрестие с апертурой и зелёный маркер. Превью проходит ту же тесселяцию по фактическому DPI, но его данные не попадают в кэш сцены. Конец — квадрат, середина — треугольник, центр — окружность, пересечение — крест, ближайшая точка — «песочные часы».

### Привязки и рамка

`SnapEngine::find` переводит радиус 9 логических пикселей в мир (`r = 9/z`) и вызывает `doc.query` для квадрата вокруг курсора. Узкая фаза отсекает точки вне **круга** апертуры. Центр короткой дуги может лежать вне её геометрического AABB: отдельное разреженное R-tree хранит только такие внешние центры и точки вставки. Обе версии индекса публикуются в одной транзакции, в том числе при Undo/Redo; вспомогательные точки не увеличивают Zoom Extents.

Внутри апертуры выбирается ближайший включённый характерный кандидат: конец, середина, центр, пересечение, а при соответствующей маске также квадрант или точка вставки; при равном расстоянии выбор детерминирован по типу и ID. Если их нет, Nearest проецирует на сам штрих. Иначе ближайшая проекция на отрезок почти всегда «побеждала» бы его середину. Можно передать маску, например только `Nearest` для щелчка выбора. Пересечения вычисляются для локальных пар отрезок/отрезок, отрезок/окружность и окружность/окружность с отсечением по **обоим** sweep. Совпадающие полные окружности не создают произвольную точку пересечения. Стоимость зависит от локальной плотности: для `m` рёбер в апертуре в худшем случае `O(m²)` пар, а не обещание константного времени на наложенной геометрии.

Слева направо **синее сплошное окно** принимает лишь объект целиком. Справа налево **зелёная штриховая рамка** принимает и пересечённый штрих. Совпадения AABB недостаточно: проверяются ограниченный отрезок или пересечения кривой с границей рамки, для текста — отображаемые контуры. Рамка внутри пустой окружности её не выбирает. Выбор и движение горячей ручки не создают шагов истории. Для попадания в ручку используется квадрат ±5 логических пикселей. Пока она активна, OSNAP исключает сам изменяемый объект. Последующая проекция по F8/F10 используется и для оверлея, и для подтверждения. До первого явного выбора учитывается модельный `traits.isSelected`, затем действует локальный набор ID. При удалении/скрытии объекта выбор очищается для этого ID, а привязка пересчитывается даже под неподвижным курсором.

## Проверки и пределы результата

Из [инструкции сборки Windows](../README.md):

```bat
cmake --preset windows-msvc
cmake --build --preset windows-msvc
ctest --preset windows-msvc
build\windows-msvc\bin\pd_view_tests.exe --gtest_filter=SnapScale.*
rem Отдельно, в графической сессии с драйвером desktop GL 4.5 Core:
build\windows-msvc\bin\pd_gl_tests.exe
```

* [Headless-тесты](../tests/view_math_test.cpp): переход мир↔экран и float-матрица около `1e7` с допуском 0,002 логического пикселя в проверяемом сценарии, якорь колеса, root extents, физический допуск кривых, R-tree + точная рамка, внешний центр после Undo, dirty-пакеты, DPI/LOD, ручки и маркеры. Работают и с `windows-core`.
* [Нагрузочный тест](../tests/snap_scale_test.cpp) строит **50 000 пар отрезок + окружность** в одной транзакции. 10 000 детерминированных запросов настоящего `SnapEngine::find`, включены пять видов привязки по умолчанию; проверяются тип, координаты и ID владельцев. В одном прогоне Linux x86-64 Release, GCC 12.2, 2 vCPU Xeon 2,60 ГГц: создание сцены 0,195 с, медиана поиска 1,85 мкс, p95 3,04 мкс, p99 4,60 мкс. Это разделённые ячейки с локальными пересечениями, **не** замер GPU, FPS или тяжёлого случая с 100k наложенных штрихов. Время печатается, а не служит нестабильным порогом CI.
* [Тест окна](../tests/window_test.cpp) посылает события мыши настоящему `Viewport` и проверяет выбор рамкой, два привязанных клика `_LINE`, удаление/возврат маркера без движения мыши. [Проверки редактора](../tests/editor_window_test.cpp) добавляют клики, Enter и Esc во время правки, накопление выбора, привязку и ограничение ручек. Этим тестам не нужен GPU.
* [Тест FBO](../tests/gl_smoke_test.cpp) показывает настоящий `QOpenGLWidget`, компилирует встроенные GLSL, читает кадры и проверяет цвета пяти типов геометрии, сетку, выделение/ручки и Undo/Redo. При перетаскивании сравнивается участок **нового штриха в стороне от курсора**; Esc возвращает исходный кадр, `_UNDO`/`_REDO` после подтверждения возвращают соответствующие кадры целиком. Его можно включить в CTest при configure через `-DPLANEDRAFT_TEST_GL=ON`. В Linux проверен на Qt 6.5 и программном Mesa llvmpipe 4.5 Core, в том числе с `QT_SCALE_FACTOR=1.5` и `2`. Это проверка отрисовки, **не** аттестация драйвера Windows. В проект не включены тестовый QPA-адаптер или бинарники Mesa.

Вставки рисуются рекурсивно с цветом эффективного слоя / `ByBlock`. Для закрашенных стрелок и Solid есть отдельный диапазон треугольников VBO. Клик в заливку и пересекающая её рамка учитывают площадь, а не только рёбра. Узкая фаза по вставке возвращает ID верхнего уровня, даже если найден штрих вложенного члена.

**Лист.** `drawPage` рисует тень, белый прямоугольник бумаги и результат общего `visitPage`. Отрезки и контуры глифов в `double` отсекаются прямоугольником вида, у заполненного треугольника отсекается многоугольник и строится веер. Только затем вершины переводятся в RTE `float`. Переключение обратно восстанавливает камеру модели. В FBO-тестах проверяются цветные пиксели на обоих концах ограниченного вида и их отсутствие снаружи, видимый штрих размера, пустой остров в сплошной заливке и исходный кадр после возврата.

Экранный штрих — hairline. Текст контурный, не MText/SHX; физический вес линий задаётся в векторном экспорте. Для приёмки цели **60 FPS** нужен отдельный замер p95 времени кадра на целевом Windows GPU при фиксированных DPI, размере окна и трассе pan/zoom. Ни тест поиска, ни VSync его не заменяют.
