# PlaneDraft Lisp: команды для активного чертежа

`pd_scripting` — работающий встроенный интерпретатор. Приложение вызывает [IScriptEngine](script_engine.hpp), передавая UTF-8 исходник, имя источника для диагностики и контекст активного документа. [Пример `pattern.pdl`](../examples/scripts/pattern.pdl) можно запустить без установки каких-либо пакетов:

```text
_RUNSCRIPT "C:\путь к проекту\examples\scripts\pattern.pdl"
_SHIFTSEL 15
```

Сначала запустите файл, затем выберите объекты и выполните вторую команду. В RU те же имена — `ЗАПУСТИТЬСКРИПТ` и `СДВИГВЫБОРА`. Это собственный **малый Lisp**, а не AutoLISP, реализация стандарта Scheme или Python. Выбор сохраняет автономную сборку на C++20 без ещё одного runtime, пакетов и путей поиска модулей. Лицензия pybind11 (BSD) не покрывает интерпретатор CPython (PSF и др., вне заданного перечня); Scheme-библиотека тоже потребовала бы отдельного аудита. Цена решения — небольшой фиксированный язык, без совместимости с библиотеками этих систем. Код движка — LGPL-2.1-or-later.

## Документ и транзакция

```lisp
(with-transaction doc "Контур"
  (let* ((l (add_layer doc "Контур" (list 80 190 240)))
         (p (add_polyline doc (list (list 0 0) (list 20 0 0.5) (list 20 10)) #t l)))
    (print "ID:" p "вершины:" (get (entity doc p) "vertices"))))
```

* `doc` — текущий документ, а не указатель C++; `(entities doc)`, `(layers doc)`, `(selection doc)` — списки ID. Положительные целочисленные литералы и ID хранятся как `uint64`, без преобразования через `double`. Геометрия и арифметика — `double`.
* `(layer doc id)` и `(entity doc id)` возвращают записи (списки пар), `(get запись "имя")` — поле. У всех сущностей доступны `id`, `layer`, `type`, `bounds`; остальные поля зависят от типа, например `vertices` и `closed`, `center` и `radius`. У слоя — `id`, `name`, `color`, `linetype`, `weight`, `visible`, `frozen`, `locked`.
* `(query_box doc min-xy max-xy [visible-only])` возвращает ID кандидатов из **R-tree**, по умолчанию только видимых. `xy` — список двух чисел. Перечисления и запрос области читают опубликованный документ; чтение по ID видит также созданный или преобразованный объект текущей транзакции. `(selection doc)` читает текущий выбор видового экрана, не дублируя его в истории.
* Только внутри `(with-transaction doc "метка" выражение ...)` допускается запись. Метка — описание группы в исходнике, не отдельная запись журнала. **Один запуск файла или пользовательской команды — максимум один шаг Undo**: последовательные блоки работают в общей области подготовки, вложенные запрещены. На исключении интерпретатора или ядра выбрасывается вся группа: нет неполных слоёв, объектов, обновлений индекса/экрана или лишнего шага истории. Пустая операция сохраняет Redo. Валидация и публикация — те же `Transaction` и `Document::transact`, что в [нативном SDK](../sdk/README.md).

| Вызов внутри блока (квадратные скобки обозначают необязательный аргумент) | Результат |
|---|---|
| `(add_layer doc name [rgb])` | ID нового слоя; `rgb` — три целых 0–255. Имя должно быть уникальным. |
| `(add_line doc start end [layer-id])`, `(add_circle doc center radius [layer-id])` | ID сущности, по умолчанию на слое 0. |
| `(add_arc doc center radius start-angle sweep [layer-id])` | Направленная дуга, углы в радианах. |
| `(add_polyline doc vertices closed [layer-id])` | Вершина `(list x y [bulge])`; `closed` — `#t`/`#f`. Bulge относится к исходящему ребру. |
| `(add_text doc string ink-min ink-max matrix [layer-id])` | Текст с локальными метриками и размещением. |
| `(transform doc id matrix)`, `(delete doc id)` | Преобразовать/удалить сущность. `matrix` — список `(a b tx c d ty)`, например перенос `(list 1 0 10 0 1 0)`. |

## Язык и регистрация

Файл UTF-8 (допустим BOM), `;` начинает комментарий до конца строки. Формы — `(имя аргументы ...)`, имена функций и переменных регистрозависимы. Строки в двойных кавычках поддерживают `\"`, `\\`, `\n`, `\t`; числа используют точку. Работают `define`, `let`/`let*`, `begin`, `if` (обе ветви обязательны, условие строго логическое), `defun`, `for (i число)` (от нуля), `foreach (i список)`, `list`, `length`, `nth` (список, индекс), `+ - * /`, `= < >`, `sin`, `cos`, `pi`, `number` (преобразование строки). Без кавычек `()` — пустой список. `print` и `eprint` пишут строки в два потока командной консоли, `error` прерывает выполнение. Ошибки чтения/вычисления содержат имя файла, строку и столбец в байтах UTF-8.

```lisp
(defcommand "COUNTSEL" "СКОЛЬКОВЫБРАНО"
  (print "Выбрано:" (length (selection doc))))
```

Определения команд публикуются только после успешного завершения файла. Команда хранит тело, захваченные значения и доступные при определении функции, но не указатель на текущую транзакцию/выделение. При каждом вызове `args` — строка аргументов, `doc` — документ вызова. Команды живут до конца сессии; Undo чертежа не снимает регистрацию. Повторная регистрация того же имени — ошибка, включая конфликт с нативной командой или с именем в другом языке. Поэтому демонстрационный файл запускайте один раз за сессию.

**Проверка отказа:** запустите файл с кодом ниже. В консоли появится диагностика с `остановка`, но первая окружность не появится; прежние геометрия, R-tree и возможность Redo сохранятся. Сообщения `print`/`eprint`, уже увиденные пользователем, не откатываются.

```lisp
(with-transaction doc "Проверка отката"
  (add_circle doc (list 1 2) 4)
  (error "остановка"))
```

Нет `eval`, импорта нативных библиотек, файловых операций из языка или запуска процессов. Чтение файла выполняет `_RUNSCRIPT`. Есть пределы на исходник (1 МиБ), число/вложенность форм, шаги вычисления, глубину списков и текстовый вывод. Это предохранители от ошибок, **не** строгая квота CPU/памяти и не изоляция процесса. Запускайте доверенные скрипты: они могут менять активный чертёж и выполняются синхронно в его потоке. Реализация: [reader](lisp_reader.cpp), [вычисление и команды](lisp_engine.cpp), [DOM](lisp_dom.cpp); проверки — [headless](../tests/extensions_test.cpp) и [через `_RUNSCRIPT`](../tests/session_test.cpp).
