# Объектное ядро PlaneDraft

`pd_core` — статическая библиотека C++20. Публичные заголовки — в `include/planedraft/`; в зависимостях нет ни Qt, ни OpenGL, ни сторонней геометрической библиотеки. Через DLL проходит только [версионированный C ABI](../sdk/README.md), а не эти C++-классы. Единица владения, редактирования и истории — один `Document`.

## Модель памяти

* **Handle не является адресом.** `EntityId`, `LayerId`, `BlockId` — 64-битные номера из одного пространства документа. Слот 0 — изначальный слой `0`; прототип сущности имеет ID 0 до добавления. Приложение ссылается на объекты по ID. Даже если транзакция оборвалась или ветку redo отбросили, выданные номера не используются снова **в пределах того же чертежа**. Открытие другого файла начинает новое пространство ID. Undo/Redo восстанавливают прежний ID.
* Активная база — непрерывный `vector` слотов, логически образующий таблицы примитивов, слоёв и определений блоков. Тег слота отличает эти типы и пустое место. Поиск `entity(id)` — O(1), без хеширования, удаление не сдвигает соседей. Геометрия разных размеров полиморфна и размещена **отдельно**, а вершины полилинии — в одном `vector<Vertex>`. Это не обещание, что сами полиморфные объекты лежат непрерывно.
* При добавлении ядро клонирует пользовательский прототип. Опубликованное значение — `shared_ptr<const T>`: слот и записи истории разделяют его **без изменяемого алиаса**. Правка геометрии работает с приватным `unique_ptr<Entity>` от `clone()`. После валидации он становится новой неизменяемой версией. Повторный ход истории переставляет ссылки, а не пересчитывает координаты обратной матрицей. Сырые указатели из `entity()`/`layer()` заимствованы только до следующей правки.
* Цена выбора: отдельные аллокации и счётчики ссылок, таблица до наибольшего опубликованного handle и память под изменённые версии в истории. История пока не ограничена по размеру. Полная выдача `entityIds()` сканирует слоты в порядке ID и предназначена, например, для сериализатора, **не** для выбора мышью. Будущие разреженные внешние handles нужно отображать на внутренние ID, а не использовать как размер вектора.

## Граница транзакции

```text
transact(lambda)           apply: подготовка             commit
  Transaction               fork корня R-tree              активные слоты + корень
  id → (before, after)  →    erase(old), insert(new)   →    курсор UndoStack + revision
  валидация прототипов       подготовка памяти и Change[]    одно уведомление с Change[]
```

`add`, `transform` и `remove` у документа — сокращения для однооперационной транзакции. В `transact` можно также вызвать `replace`, `addLayer`, `updateLayer`, `removeLayer`, `defineBlock`. Нельзя удалить слой `0` или слой, на который ссылаются модель, определение блока, объект листа или вид. Проверяется состояние с учётом уже подготовленных операций транзакции. Операции транзакции видят предыдущие операции той же группы; читатель `Document` до commit видит только старую ревизию. На каждый ID запоминается одно **начальное** и одно **конечное** значение. `add` → `remove` в одной группе не создаёт пустого undo-шага. Идентичность объекта не меняется при замене геометрии.

1. Сначала проверяются типы, ID, принадлежность блока, существование и блокировка слоёв, допустимость геометрии. Если из callback вышло исключение, его дельты уничтожаются.
2. Готовится независимая версия индекса. Удаляется **точный прежний AABB**, добавляется новый; при одинаковых AABB основной геометрический индекс не редактируется. Выделение памяти, в том числе под события и запись истории, предшествует публикации. Ошибка не меняет активную геометрию, индекс, ревизию и redo-ветку.
3. Группа публикуется за один шаг истории и одну ревизию. Undo меняет местами `before/after` в обратном порядке, redo — в прямом. Оба проходят тот же путь обновления индекса. Новая успешная правка после undo отбрасывает только redo-хвост.
4. `observe(fn)` вызывается после commit, включая undo/redo. Callback получает заимствованный `span<const Change>` **только на время вызова**. Для редактирования `object` отличает сущность, слой и блок; `kind` — `Added`, `Modified`, `Removed`. При замене чертежа `object` — `Document`, `kind` — `Reset`. Для удаления достаточно ID — объект уже может отсутствовать. Обработчик может читать документ и индекс в окончательном состоянии. Токен подписки удерживает callback, документ хранит слабую ссылку. Уничтожение токена отключает подписку. Исключение наблюдателя не отменяет сделанную правку и не прерывает остальных: первую ошибку можно забрать через `takeObserverError()`.

Документ предназначен для **одного потока-владельца**; чтение одновременно с записью без внешней синхронизации недопустимо. Вложенные записи, в том числе из callback наблюдателя, отклоняются. Фоновому клиенту нужны собственные данные/снимок, а не сохранённый `span`.

## Пространственный поиск

Интерфейс [`SpatialIndex`](include/planedraft/spatial/spatial_index.hpp) принимает `(id, bounds)`, поддерживает `erase`, `query` и изолированный `fork`. Реализация — [динамическое R-tree](spatial/r_tree.cpp) с равноудалёнными от корня листьями. Страница содержит до 8 записей, некорневая — не менее 4. Выбор поддерева минимизирует увеличение полупериметра; при переполнении записи делятся по медиане центров вдоль оси большего разброса. После удаления малозаполненные страницы сливаются или перераспределяются с соседом; корень с единственным поддеревом сжимается.

Страницы неизменяемы: `fork` разделяет корень, запись копирует **путь и затронутых соседей**, а не весь индекс. История не удерживает прежние деревья. Запрос спускается только в пересекающиеся AABB. При локальном запросе по хорошо разделённой сцене ожидаем O(log N + k) работы при k ответах; перекрывающиеся AABB или окно на весь чертёж могут потребовать O(N). Порядок ID результата не определён.

`Document::query(box)` по умолчанию убирает невидимые сущности и скрытые/замороженные слои; `query(box, false)` возвращает все пространственные совпадения. Блокировка не мешает выбору, но мешает правке. Это **поиск кандидатов**, не точное попадание в штрих: для OSNAP нужно проверить расстояние/пересечение с аналитической кривой. `Document::extents()` возвращает уже вычисленный AABB корня (все слои, O(1)). Центр короткой дуги или точка вставки текста могут лежать **вне** геометрического AABB: `queryExtraPoints` запрашивает отдельное разреженное дерево таких точек. Основной индекс остаётся точным по геометрическим габаритам; обновления обоих деревьев и слотов атомарны с точки зрения наблюдателя. Использование обоих запросов для привязок и ручек описано в [архитектуре видового экрана](../render/README.md).

## Геометрические соглашения

* IEEE 754 binary64, Y вверх, углы в радианах. `EPSILON = 1e-9` — модельный допуск, не допуск экрана в пикселях. Для ортогональности/сходства матрицы сравниваются нормированные базисные векторы. Это арифметика `double`, а не произвольная точность: у очень больших координат шаг представимых значений может превышать `EPSILON`.
* AABB замкнут: касание границ — совпадение. Пустой AABB — нейтральный элемент объединения, а не прямоугольник в начале координат. Матрицы действуют на столбцы: `T * R * S` сначала масштабирует, затем поворачивает и переносит. Отражение задаётся точкой и направлением оси.
* [`curves.hpp`](include/planedraft/math/curves.hpp) различает касание, два пересечения, отрезок перекрытия и совпадающие окружности. Есть проекция на ограниченный отрезок, окружность и направленную дугу. Неопределённая проекция центра на окружность детерминированно выбирает `+X`.
* `Vertex::bulge = tan(sweep/4)` относится к **исходящему** сегменту: 0 — прямая, знак задаёт направление, `abs(bulge)>1` — большая дуга. У открытой полилинии последняя вершина не имеет исходящего сегмента; у замкнутой её bulge относится к ребру на первую вершину. Границы учитывают экстремумы фактической дуги, а не только вершины. Середина дугового ребра вычисляется через стрелу прогиба. Маска OSNAP управляет выдачей характерных точек; кандидаты разных типов могут совпадать.
* Сходство сохраняет окружность и круговую дугу, отражение меняет знак sweep/bulge. Неравномерное масштабирование или сдвиг со скосом, превращающие окружность в эллипс, **отклоняются** для круговой геометрии, а не подменяются «средним радиусом». Для линейного сегмента и прямолинейной полилинии аффинное преобразование допустимо, пока ребро не вырождается.
* `Text` хранит строку UTF-8, локальный прямоугольник метрик и матрицу размещения: ядро не угадывает ширину текста из числа символов. `BlockDefinition` владеет неизменяемыми локальными сущностями с собственными ID. `BlockReference` разделяет определение и хранит размещение. Ссылаться можно только на уже определённые блоки этого документа, поэтому циклы не создаются. В глобальном индексе модели — **вставка** с консервативным AABB; в каждом определении — разделяемое локальное R-tree членов с учётом выносных центров дуг и точек вставки. При запросе с окном проверяются преобразованные границы узлов; не нужно дублировать дерево для каждого экземпляра. Редактирование определения «на месте» не предоставляется.
* `resolveStyle` разрешает явные значения, `ByLayer` и `ByBlock` для цвета, типа и веса линии. Для члена блока вызывающая сторона передаёт разрешённый стиль вставки; вне блока `ByBlock` использует слой. Имена слоёв и блоков уникальны внутри своих таблиц с посимвольным сравнением UTF-8, ссылки всё равно идут по ID.

## Операции редактирования

[`pd::edit`](include/planedraft/edit.hpp) возвращает `Plan` по `const Document&`: 64-битный ID для замены, ID 0 для добавления, отсутствие нового значения для удаления. Это **не открытая транзакция**. План владеет прототипами, а сам документ должен его пережить. Ни построение, ни уничтожение плана не меняют модель, индексы, счётчик ID или историю. Только `plan.apply(document)` проверяет исходную ревизию и переносит все записи в одну `Transaction`. Отказ на одном из элементов группы не публикует остальные.

* [Аффинные операции и ручки](edit/plan.cpp) клонируют либо перестраивают геометрию с сохранением свойств. Преобразование текста действует на матрицу размещения. Масштаб, ось отражения, полярное/ортогональное ограничения и перестроение дуги по трём точкам не зависят от камеры или DPI.
* [Обрезка и удлинение](edit/trim_extend.cpp) используют [аналитические рёбра](include/planedraft/math/edges.hpp), общие с OSNAP. Для Trim параметры пересечений сортируются вдоль пути (номер ребра + доля), включая переход через шов. Первый оставшийся фрагмент наследует ID; второй, если есть, получит новый ID при commit. Окружность может сменить тип на дугу **без смены ID**. Extend перебирает пересечения опоры с конечными границами и минимизирует положительную длину/угол до попадания, не укорачивая цель.
* [Offset и Fillet](edit/offset_fillet.cpp) работают с опорными прямыми и окружностями, не с хордами тесселяции. Для проверки самопересечений смещённой полилинии используется отдельный временный пространственный индекс рёбер, не индекс документа. Для двух сохраняемых лучей с углом `θ` точки касания отстоят от угла на `R / tan(θ/2)`. При `R = 0` добавления дуги нет. Допуски и пределы `double` те же, что в остальном ядре.

[Геометрические тесты](../tests/edit_test.cpp) можно запускать отдельно: `ctest --test-dir build/core -R ^editing$ --output-on-failure`. В них проверены в том числе тип/ID и индекс после обрезки, касательность к обоим отрезкам, знак bulge при отражении, сворачивание offset и отказ устаревшего плана. [Справка команд](../editor/README.md) показывает, как получить те же операции с холста.

## Пример и проверка

Исполняемый короткий пример — [`Document.MoveGroupAndFindItByArea`](../tests/document_test.cpp): создать отрезок и окружность, перенести оба в одной транзакции, найти отрезок в новом окне, сделать undo и убедиться, что ID снова находится **только** в старом окне. Там же — проверка массива из 1000 объектов и отказа индекса посередине записи. [Тест R-tree](../tests/spatial_test.cpp) сверяет запросы с полным проходом после разбиений, перемещений и слияний.

```sh
# Нужны C++20, CMake, Ninja и установленный GoogleTest. Qt не ищется.
cmake -S . -B build/core -G Ninja -DPLANEDRAFT_BUILD_GUI=OFF -DCMAKE_BUILD_TYPE=Release
cmake --build build/core
ctest --test-dir build/core --output-on-failure
```

Полный headless-прогон с ASan и UBSan (Linux, GCC/Clang, без Qt/GL):

```sh
cmake -S . -B build/sanitize -G Ninja -DCMAKE_BUILD_TYPE=Debug -DPLANEDRAFT_BUILD_GUI=OFF -DPLANEDRAFT_SANITIZE=ON
cmake --build build/sanitize
ASAN_OPTIONS=detect_leaks=1:halt_on_error=1 UBSAN_OPTIONS=halt_on_error=1:print_stacktrace=1 ctest --test-dir build/sanitize --output-on-failure
```

На Windows с закреплённым vcpkg из [основного README](../README.md): `cmake --preset windows-core`, `cmake --build --preset windows-core`, `ctest --preset windows-core`. Этот preset отключает и GUI-цели, и Qt-порты манифеста. Для одной библиотеки без GoogleTest используйте `-DBUILD_TESTING=OFF` и цель `pd_core` без toolchain vcpkg.

Открытие файла — не обычная транзакция редактирования. `replaceContents` принимает подготовленный документ, заменяет оба индекса/слоты, очищает историю и уведомляет существующие подписки одним `Reset`. ID относятся к новому чертежу. [Контракт ввода-вывода](../io/README.md).

## Геометрия оформления

* [Dimension и Hatch](include/planedraft/entities/annotation.hpp) хранят определяющие точки / замкнутые контуры и параметры. Их производные примитивы неизменяемы и не получают ID в документе. `Dimension::withPoint` пересчитывает значение и геометрию; ручки используют обычный план правки.
* [Построитель штриховки](drafting/hatch.cpp) работает **без Qt/GL**. Для каждой семьи штрихов координаты считаются от начала узора; дуги делятся в экстремумах на монотонные участки. Пересечения упорядочиваются вдоль строки и попарно ограничивают отрезки (чётность, полуоткрытые интервалы). У бетона дополнительно режутся штрихи/промежутки. Сплошная заливка режет плоские контуры на полосы и треугольники; дуги для неё аппроксимируются с допуском хорды 0,01 единицы. Для не пересекающих друг друга простых петель учитываются и отверстия, и острова внутри отверстий. Плотность узора, число частей и работа сканирования ограничены. Рендерер и экспортеры **не строят собственную штриховку**.
* [Обход графики](drafting/drawing.cpp) раскрывает вставку с накопленной матрицей, эффективным слоем и родительским стилем. Перед загрузкой граф имён упорядочивается с проверкой циклов (`CircularReferenceError`); предел глубины — 64, развёрнутого определения — 200 000 элементов. Геометрия, которую INSERT аффинно растягивает в эллипс, аппроксимируется для показа/разложения (допуск хорды 0,01 в пространстве вывода), **без** изменения определения. `explode` возвращает один привязанный к ревизии план для всего набора.
* [Layout / ViewportEntity](include/planedraft/layout.hpp): ориентация, поля, надпись, листовая геометрия и виды живут отдельно от extents модели. Для центра прямоугольника `C`, цели `T` и масштаба `s` бумажная точка равна `C + s·(p − T)`. `visitPage` передаёт принятые примитивы в мм и прямоугольник отсечения; GL, SVG и PDF обязаны отсечь **всю краску**, в том числе текст и заливки. Добавление/изменение настроек листа публикуется как обычная транзакция, смена вкладки — нет.
