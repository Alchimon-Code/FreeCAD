# Шаг 4. Расширения PlaneDraft

Есть два способа добавить команду: динамическая библиотека через [публичный C ABI](include/planedraft/pd_plugin_api.h) и файл [PlaneDraft Lisp](../scripting/README.md). Оба работают с **тем же активным `Document`**, что и `_LINE`. Ни один из них не получает `Entity*`, список объектов Qt или контекст OpenGL.

## Попробовать на готовой сборке

1. Запустите `build\windows-msvc\bin\PlaneDraft.exe --load-plugins` либо выберите в меню «Файл» загрузку доверенных модулей из `plugins/`. В дереве сборки это каталог **рядом с `bin/`**, не каталог текущего чертежа. Можно также загрузить одну DLL по абсолютному пути.
2. Введите `_FRAME 100` (в русской локализации — `РАМКА 100`), затем `Ctrl+Shift+E`. [Пример на C11](../examples/plugins/frame_generator/frame.c) строит замкнутую полилинию шириной 100 и высотой 50, четыре окружности и надпись. Если слоя `Frame` нет, команда создаёт и его. `_UNDO` отменяет **всю** рамку; `_REDO` работает даже после «Файл → Выгрузить плагин…».
3. «Файл → Запустить скрипт…» → [`pattern.pdl`](../examples/scripts/pattern.pdl). То же из консоли: `_RUNSCRIPT "полный путь с пробелами/pattern.pdl"`, в RU — `ЗАПУСТИТЬСКРИПТ`. Скрипт строит делительную окружность с восемью отверстиями и регистрирует `_SHIFTSEL`. Выберите объекты и введите `_SHIFTSEL 15`: сдвинется **только текущее выделение**, на 15 единиц вправо. `_UNDO` сначала отменит сдвиг, следующий — построение. Код скрипта не запускается автоматически из чертежа.

В многодокументном окне реестр расширений принадлежит вкладке. Явный `--load-plugins` загружает доверенную папку для открываемых в этом окне документов; ручная загрузка DLL и запуск `.pdl` относятся к активному документу. В [переносимом Windows-комплекте](../packaging/windows/README.md) примеры лежат в тех же каталогах относительно `bin/`; для внешнего модуля используйте `include/pd_plugin_api.h` или совместимый путь `include/planedraft/pd_plugin_api.h`.

## Один интерфейс для стороннего модуля

При сборке обычной CMake-цели `frame_generator` результат помещается в `build/<preset>/plugins/`; цель зависит только от include-каталога `pd_sdk`. **Вне дерева сборки** достаточно скопировать заголовок, MIT-уведомление и собственный исходник. Например, из корня checkout:

```bat
:: x64 Native Tools Command Prompt for VS 2022
cl /nologo /std:c11 /utf-8 /LD /DPD_BUILD_PLUGIN /Isdk\include examples\plugins\frame_generator\frame.c /link /OUT:frame_generator.dll
```

```sh
cc -std=c11 -shared -fPIC -fvisibility=hidden -DPD_BUILD_PLUGIN -Isdk/include \
   examples/plugins/frame_generator/frame.c -o frame_generator.so
```

Нет импортной библиотеки хоста, pybind11, Qt или связи с C++ ядром. Для генерации справочника таблиц: `doxygen docs/Doxyfile` (не нужен при сборке приложения). Публичные заголовки и примеры — **MIT**, реализация хоста и интерпретатора — **LGPL-2.1-or-later**. Собственную лицензию модуля выбирает его автор; см. [условия и ограничения поставки](../docs/LICENSING.md).

### Переговоры о версии и время жизни

| | ABI v1 | ABI v2 |
|---|---|---|
| Экспорт | `pd_plugin_query(1)` из неизменённого [`plugin.h`](include/planedraft/plugin.h) | `pd_plugin_query_v2(2)` из `pd_plugin_api.h` |
| Проверка | `abi_version`, `struct_size`, имя и `run` | `api_version`, минимальный `struct_size`, `init`, `shutdown` |
| Команды | Одна, без аргументов; каждый успешный `add_line` по старому контракту — отдельная правка | `init` может зарегистрировать несколько имён с `run` и `void* user`; `run` получает таблицу хоста и строку аргументов без имени команды |

* Разрядность процесса и модуля должны совпадать. Стандартная упаковка структур, `__cdecl` на Windows, POD, фиксированные целые, `double`, NUL-терминированный UTF-8. Не передавать между CRT строки STL, аллокаторы, исключения, Qt-типы, `FILE*` или объекты с виртуальными методами. Запрос возвращает **неизменяемый, принадлежащий модулю** дескриптор до выгрузки. Не изменять префиксы, порядок или размер существующего union; хвост проверять через `PD_FIELD_END`. `PD_*_V2_MIN_SIZE` — размеры обязательных префиксов.
* Менеджер вызывает `LoadLibraryExW` (Unicode-вариант LoadLibrary с ограничением поиска зависимостей) или `dlopen(RTLD_NOW | RTLD_LOCAL)`. Сначала проверяет символ v2; к v1 переходит **только при отсутствии** v2. Ошибочная версия/размер не ведёт к вызову `init` или скрытому откату к другому ABI. Старые DLL не нужно перекомпилировать.
* Все операции синхронны в потоке документа. Таблица `PdRegistrarV2` заимствована только на `init`; состояние модуля и его пользовательские данные остаются у модуля. Все регистрации сначала приватные. Несовместимость, ошибка `init` или конфликт любого EN/RU-имени отвергают весь модуль. После попытки `init` вызывается `shutdown(instance)` даже при ошибке; при частичном `init` он должен уметь освобождать и частичное/пустое состояние. До попытки `init` `shutdown` не вызывается.
* При выгрузке сначала удаляются **все** имена владельца. Уже вызванная команда удерживает библиотеку до выхода; затем `shutdown` (без вызовов хоста) и `FreeLibrary`/`dlclose`. Плагин обязан завершить свою работу и не оставлять обработчиков в чужих потоках. В DOM остаются только объекты, созданные хостом. При сканировании берутся прямые файлы библиотек без symlink, в порядке имён; отказ одного файла записывается в консоль и не мешает остальным.
* DLL — **доверенный машинный код в процессе**, не песочница. В частности, системный загрузчик выполняет статические инициализаторы ещё до проверки экспортной таблицы. ABI-проверки не делают произвольный указатель безопасным и не изолируют падение чужой DLL. Каталог сканируется только по команде пользователя или с `--load-plugins`.

### Запись, чтение и выделение

1. Хост выдаёт `PdHostV2` и `PdDocumentHandle` **на один вызов `run`**. Дескрипторы документа/транзакции — разные непрозрачные токены, не адреса. Стабильный `PdId` — идентификатор объекта в документе, не разрешение на запись.
2. `pd_begin_transaction` открывает одну группу. Передавайте дескрипторы c заполненным `struct_size` в `pd_add_entity`/`pd_add_layer`, `pd_transform` и `pd_delete` принимают ID сущности. Поддержаны Line, Circle, Arc (радианы), Polyline (исходящий bulge, включая замыкающее ребро), Text (строка, локальный ink-AABB, матрица 2×3), свойства ByLayer/ByBlock/явные, видимость и свойства слоя. Слой 0 существует изначально. Матрица `(a b tx; c d ty)` действует на столбец `(x,y,1)`. Валидация геометрии и блокировки слоёв — та же, что в ядре.
3. Запись копирует аргументы во владение хоста. Чтение по ID видит более ранние операции этой группы. `pd_read_entity`, `pd_read_layer`, `pd_entities`, `pd_layers`, `pd_selection`, `pd_query_box` возвращают **снимки**, не живые контейнеры. Перечисления и R-tree видят *опубликованный* документ; `pd_selection` — эффективные видимые ID текущего редактора, не только исходный флаг `PD_SELECTED`. Пространственный запрос даёт кандидатов по замкнутому AABB, по флагу исключая невидимые и замороженные слои; это не проверка попадания в кривую.
4. Освобождайте результат **через `host->pd_free_buffer(doc, root)`**: передавайте корневой указатель записи или `PdIds.data`, не строку/вершину внутри. `NULL` допустим. Никогда не вызывайте `free`/`delete` над этими указателями; после освобождения их нельзя использовать. Хост забирает оставшиеся буферы при возврате из команды. Для долговременного хранения скопируйте данные на своей стороне.
5. `pd_commit(tx)` запечатывает группу; публикация происходит **после успешного возврата `PD_OK` из `run`**. `pd_rollback(tx)` отбрасывает её. Ошибка записи по действующему handle помечает группу непригодной к commit. Незакрытая группа, неуспешный статус команды (даже после commit) или исключение валидации не публикуют ничего. Это не имитация отката через `_UNDO`: ни ветка Redo, ни R-tree, ни ревизия не меняются. Выданные при попытке ID не переиспользуются в этом чертеже. ID локальны для чертежа: те же числа в другой вкладке или после замены документа в одиночной сессии могут обозначать другие объекты. Не переносите handles между чертежами. При успехе непустая группа даёт один шаг Undo и один пакет `Added/Modified/Removed`; видовой экран получает обычную инвалидацию.
6. Проверяйте `PdStatus` каждого вызова. Для сообщения — `pd_log(doc, 0, "…")`, для диагностики — поток `1`. Лог не откатывается вместе с геометрией. Шаблон с корректным порядком вызовов и обработкой ошибок — [`frame.c`](../examples/plugins/frame_generator/frame.c).

`CommandRegistry` проверяет общий словарь встроенных, нативных и скриптовых команд для обоих языков. Каноническое имя задаётся без `_`: `[A-Z][A-Z0-9_]{0,31}`. В необязательном локальном имени разрешены также заглавные русские буквы. Ввод регистронезависим: `_FRAME` всегда глобальное, `РАМКА` доступно в RU, `_РАМКА` не является подстановкой. Пользовательские алиасы не затеняют канонические имена. Хвост аргументов сохраняет внутренние пробелы; оболочка ОС не вызывается.

## Как проверять

* [`extensions_test.cpp`](../tests/extensions_test.cpp) загружает настоящие модули: границы версий и размеров, конфликт и частичный `init`, выгрузка в ходе callback, повторная загрузка, буферы и устаревшие handles, пять дескрипторов, явный rollback и неуспешный возврат после commit. Отдельный тест v1 проверяет старую семантику `add_line`. С тем же документом проверяются скриптовые транзакции и команды. Для этого набора **Qt не нужен**.
* [`session_test.cpp`](../tests/session_test.cpp) проходит через строку команды, включая имена RU, `_`, каталог с неисправным модулем и путь с Unicode/пробелами. `_FRAME` публикует шесть сущностей + слой одним пакетом, пространственный запрос находит геометрию, `_UNDO` возвращает пустой индекс. `_RUNSCRIPT` проверяется как с рабочим примером, так и с ошибкой после записи; диагностика идёт в stderr.
* [`window_test.cpp`](../tests/window_test.cpp) использует выбор мышью, а не заглушку списка ID. Опциональный [`viewport_fbo`](../tests/gl_smoke_test.cpp) проверяет пиксели настоящего `QOpenGLWidget` после `_FRAME`, выгрузки, `_UNDO` и `_REDO`.

```sh
# Linux, GCC/Clang + GoogleTest. Инструментируются также загружаемые тестовые .so.
cmake -S . -B build/san -G Ninja -DPLANEDRAFT_BUILD_GUI=OFF -DBUILD_TESTING=ON \
  -DPLANEDRAFT_SANITIZE=ON -DCMAKE_BUILD_TYPE=Debug
cmake --build build/san
ASAN_OPTIONS=detect_leaks=1:halt_on_error=1 UBSAN_OPTIONS=halt_on_error=1:print_stacktrace=1 \
  ctest --test-dir build/san --output-on-failure
```

Контрольный прогон шага 4: Linux x86-64, GCC 12.2, Qt 6.5.0, Release — **6/6 CTest** (60 проверок GoogleTest) с `PLANEDRAFT_TEST_GL=ON`; framebuffer — llvmpipe/Mesa 23.1.4, OpenGL 4.5 Core (включая отдельные прогоны при 150% и 200%). Headless Debug с ASan+UBSan и обнаружением утечек — **3/3 CTest** (45 проверок: `core`, `viewport_math`, `extensions`). Это тесты Linux, не измерение аппаратного FPS и не прогон Windows. Пресеты/CI Windows собирают те же модули как DLL; аппаратную проверку на Windows выполняют отдельно.
